## 3. 정지선을 처음 판정한 직후 판정이 사라짐 — 재현 확인

- 현상: 정지선이 관심 영역 위쪽에 들어오면 판정이 참이 되었다가 다시 사라진다. `drive.py`는 첫 판정에서 정지하고 멈춘 채 확정을 기다린다. 이 위치에서 판정이 5장 연속 사라지면 오판정으로 보고 다시 출발한다. 이때 로그에 `STOP_LINE 확인 실패 — 판정 5장 연속 사라짐`이 기록된다.
- 원인: `_line_px`는 관심 영역 전체 행에서 측정한 라인 폭의 중앙값을 라인 굵기로 사용한다. 카메라 원근 때문에 이 값은 차량에 가까운 넓은 라인 폭(약 24px)에 가깝다. 정지선은 더 먼 위치에 있어 얇게 보이므로, 관심 영역 위쪽에서는 두께가 기준(0.65 × 라인 굵기)과 거의 같다.
- 근거: `agv_vision/stop_line.py:84`(`_line_px`) · `stop_line.py:110`(`need`) · `agv_control/drive.py:333` · `drive.py:419~436`(`_step_verify`)
- 재현: 곧게 다가가면 첫 판정 직후 판정이 1회 사라진다. 정지 명령 뒤 0.5w를 더 이동해 정지하면 3회 중 2회 다시 출발했다(잡음을 추가한 정지 상태 모의).
- 고칠 방향:
  - ① 라인 굵기를 정지선 높이에서 측정한다. 차량에 가까운 끝(화면 아래, 유턴 뒤에는 화면 위)에서 라인을 따라가며 줄마다 폭을 측정하고, 넓은 줄(정지선)에서 멈춘다. 정지선 바로 앞 8줄의 중앙값을 라인 굵기로 사용한다.
  - ② 판정 직후(`hold` 중)에는 두께 기준을 낮춘다(예: 0.65 → 0.5). 판정을 시작하는 기준보다 유지하는 기준을 낮게 둔다.
  - 효과: 첫 판정 직후 판정이 사라지지 않는다. 정지 명령 뒤 추가 이동 거리 0~2w에서 모두 2프레임 만에 확정했다. `test_stop_line.py`를 모두 통과했다.
  - 바닥 무늬가 검정으로 많이 추출되는 조명에서는 정지선 너머 바닥의 점이 라인 폭으로 측정되어 라인 굵기가 작아진다. ①은 이 경우도 해소한다.
  - 라인 굵기에 `LineDetector`의 값이나 고정 보정값을 사용하는 방법은 `test_tilted_stop_line[±20]`과 `test_too_tilted_is_not_stop_line`을 통과하지 못했다. 라인이 기울면 가로 단면의 폭이 넓어진다. 고정값에는 이 효과가 반영되지 않는다.

```python
# ① stop_line.py 예시 — __init__에 self.last_px = None, self.last_local = None 추가
def _line_px(self, mask, line_x):
    """차량에 가까운 끝(화면 아래, 유턴 뒤에는 화면 위)에서 라인을 따라가며 폭을 측정하고 넓은 줄(정지선)에서 멈춘다.
    정지선에 닿았으면 그 바로 앞 8줄의 중앙값 = 정지선 높이의 라인 굵기."""
    c = self.cfg
    best, best_hit = [], False
    for rows in (range(mask.shape[0] - 1, -1, -1), range(mask.shape[0])):
        ref, widths, miss, hit = line_x, [], 0, False
        for y in rows:
            near = [s for s in _spans(mask[y] > 0)
                    if s[0] - c.max_line_px / 2 <= ref <= s[1] + c.max_line_px / 2]
            if not near:
                miss += 1
                if widths and miss > 3:
                    break
                continue
            a, b = min(near, key=lambda s: abs((s[0] + s[1]) / 2 - ref))
            if b - a + 1 > c.max_line_px:          # 정지선 줄에 닿음
                if widths:
                    hit = True
                    break
                continue
            widths.append(b - a + 1)
            ref, miss = (a + b) / 2, 0
        if len(widths) > len(best):
            best, best_hit = widths, hit
    if len(best) >= 5:
        self.last_px = float(np.median(best))
        self.last_local = float(np.median(best[-8:])) if best_hit else None
    elif len(best) >= 2 and best_hit:
        self.last_local = float(np.median(best))
    if self.last_local is not None:
        return self.last_local
    return self.last_px if self.last_px is not None else float(c.default_line_px)

# ② StopLineConfig에 keep_thickness: float = 0.5 추가, _find의 need를 다음과 같이 변경
need = max(2.0, (c.keep_thickness if holding else c.min_thickness) * line_px)
```

## 4. 색 스티커가 있는 분기점을 정지선으로 판정함 — 재현 확인

- 현상: 가로선 위에 색 스티커가 있는 T자 분기점에 차량이 비스듬히(10~20°) 다가가면 정지선으로 확정한다. 곧게 다가가거나 좌우로 비켜 다가가면 발생하지 않는다.
- 원인:
  - 라인 추종은 `line_mask`로 색 스티커를 라인에 포함한다(`sticker_as_line`). 정지선 판정은 `black_mask`만 사용하므로 스티커 자리가 가로선의 빈 구간이 된다.
  - 두 스티커 사이 구간(라인 굵기의 약 4배)이 「양끝이 화면 끝에 닿지 않는 짧은 정지선」으로 판정된다.
  - 곧게 다가갈 때 발생하지 않는 이유: 가로선이 화면의 한 줄을 모두 덮으면 그 줄의 바닥 밝기 기준(상위 10%)이 테이프 밝기가 된다. 그 결과 가로선이 마스크에서 여러 부분으로 나뉘어 정지선 조건을 만족하지 않는다.
- 근거: `stop_line.py:76`(`black_mask`) · `agv_vision/line_detect.py:112~119`(`line_mask`) · `line_detect.py:164` · `line_detect.py:189`(라인 추종과 옆 갈래 판단은 `line_mask` 사용) · `stop_line.py:154`(화면 양끝 판정) · `agv_bringup/config/params.yaml:76`
- 재현(확정 프레임 수): 방향 +10° 10 · −10° 8 · +20° 5 · −20° 5 · 곧게 0 · 좌우 비킴 ±40px 0
- 고칠 방향:
  - ③ 정지선 판정에도 `line_mask`를 사용한다. 이것만 적용하면 기운 분기점의 오인식이 오히려 늘어난다(방향 +10°: 확정 10 → 17 · ①②와 함께 적용해도 14). 빈 구간이 메워져 가로선은 이어진다. 그러나 기울어 다가갈 때는 가로선의 한쪽 끝이 화면 옆이 아니라 관심 영역 위쪽으로 벗어나므로 화면 양끝 판정이 적용되지 않는다. ④와 함께 적용한다.
  - ④ 정지선으로 판정된 경우에만 분기점인지 추가로 확인한다.
    - 이어짐 확인(주): 정지선 양끝에서 바깥으로 정지선 중심선을 따라 라인 굵기 3개 길이만큼 확인한다. 확인에는 스티커를 포함하고 위아래 줄의 바닥 밝기를 기준으로 사용하는 마스크(`line_mask(..., spread=max_line_px)`)를 사용한다. 양쪽 모두 이어지면 분기점이다. 「이어짐」은 검은 화소가 절반 이상이거나, 이미 화면 가장자리이거나, 중심선이 관심 영역 위로 벗어나는 경우다.
    - 색 확인(보조): 정지선 좌우 부분 위(위아래 0.25 라인 굵기)에 스티커 색(S ≥ 100 · V ≥ 80)이 있으면 분기점이다.
    - 정지선의 세로 범위와 중심선은 라인에서 라인 굵기 1개 이상 떨어진 좌우 부분의 열로만 계산한다. 라인에 붙은 열을 포함하면 범위가 근처 스티커까지 늘어나 실제 정지선을 제외하거나, 중심선 기울기가 어긋난다.
  - 효과(①~④): 분기점 12개 조건(스티커 선명 7 · 스티커 색 약함 5)에서 오인식 0. 실제 정지선 7개 조건(곧게 · 흐림 · 좌우 비킴 · 방향 ±10° · 유턴 뒤 반대 방향 · 정지선 2w 앞 스티커)의 인식은 ①~③만 적용한 경우와 같다.
  - 시험: 아래 예시 코드와 ①②를 현재 코드에 넣은 상태에서 `test_stop_line.py` 49개를 모두 통과했다. 분기점으로 제외한 경우에도 `reason`을 남기면 진단 로그에 탈락 이유로 기록된다.
  - 색 확인만으로 처리하는 방법의 한계:
    - 스티커 색이 약하게 보이면(반사 · 흐림) 동작하지 않는다. 스티커 채도를 0.3배로 낮춘 조건에서 현재와 같은 7~11프레임을 확정했다.
    - 화면 전체에서 색을 확인하면 정지선 근처에 스티커가 있을 때 실제 정지선까지 제외한다(인식 19곳 → 8곳).
  - 위치: `StopLineDetector` 안에서 같은 프레임으로 확인한다. `drive_node`에서 `/marker/state`로 확인하면 다른 노드가 다른 시각에 판정한 결과를 사용하게 된다. 또한 색별 조건을 통과한 스티커만 전달된다.
  - 트랙 전제: 정지선의 가로선 위에는 스티커를 붙이지 않는다.
- 실차 확인: 분기점에 비스듬히 다가갈 때 진단 로그 `정지선 진단: … 판정 N`이 기록되면 이 현상이다.

```python
# ④ stop_line.py 예시
# _find: 정지선 열의 세로 구간을 runs[x] = run으로 보관하고, 판정이 참일 때 마지막에 다음을 기록한다
#   arm = [x for x in range(left, right + 1) if not np.isnan(centers[x])
#          and (x <= line_l - line_px or x >= line_r + line_px) and runs[x][1] < h - 1]
#   if len(arm) < 5: arm = list(xs)                    # 좌우 부분이 부족하면 정지선 열 전체
#   slope, b = np.polyfit(arm, centers[arm], 1)        # 정지선 중심선 y = slope·x + b
#   self.arm = (min(runs[x][0] for x in arm), max(runs[x][1] for x in arm), slope, b, left, right, line_px)
#
# process: roi = img[...] (관심 영역 BGR), mask = line_mask(roi, self.line_cfg)  ← ③
#   found, angle = self._find(mask, line_x, self.hold > 0)
#   if found and self._is_junction(roi):
#       found, angle = False, 0.0
#       self.reason = "분기점 (가로선이 양끝 너머로 이어지거나 가로선 위에 스티커)"
# self.line_cfg = line_node의 LineConfig (검정 · 스티커 기준)

def _is_junction(self, roi):
    """정지선 판정 뒤 추가 확인 — 참이면 분기점으로 보고 정지선에서 제외한다."""
    c = self.cfg
    top, bottom, slope, b, left, right, lp = self.arm
    h, w = roi.shape[:2]
    # 색 확인(보조): 정지선 좌우 부분 위에 스티커 색
    hsv = cv2.cvtColor(roi, cv2.COLOR_BGR2HSV)
    color = ((hsv[..., 1] >= 100) & (hsv[..., 2] >= 80)).astype(np.uint8)
    color = cv2.morphologyEx(color, cv2.MORPH_OPEN, np.ones((3, 3), np.uint8))
    py, px = int(round(0.25 * lp)), int(round(lp))
    if color[max(0, top - py): bottom + py + 1, max(0, left - px): right + px + 1].sum() >= 20:
        return True
    # 이어짐 확인(주): 양끝 바깥으로 중심선을 따라 라인 굵기 3개 — 둘 다 이어지면 분기점
    m = line_mask(roi, self.line_cfg, c.max_line_px) > 0      # 스티커 포함 · 위아래 바닥 기준
    half, span = max(2, round(0.5 * lp)), max(6, round(3 * lp))
    edge = max(1, int(w * c.edge_ratio))

    def goes_on(x_end, step):
        if (step < 0 and x_end < edge) or (step > 0 and x_end >= w - edge):
            return True                                        # 이미 화면 가장자리
        dark = n = 0
        for k in range(1, span + 1):
            x = x_end + step * k
            if not 0 <= x < w:
                break
            y = slope * x + b
            if int(y) - half < 0 or y >= h:
                return True                                    # 관심 영역 밖으로 벗어남
            dark += m[max(0, int(y) - half): int(y) + half + 1, x].mean() >= 0.5
            n += 1
        return n > 0 and dark / n >= 0.5

    return goes_on(left, -1) and goes_on(right, 1)
```

## 5. 처리 부하 — 참고

- 열 분석(열마다 가장 긴 세로 구간 계산)을 numpy 배열 연산으로 바꾸면 이 PC에서 파이썬 처리 시간이 4.43ms에서 2.83ms로 줄었다. 판정 결과는 같고, OpenCV 처리 시간은 제외했다. Pi에서는 측정하지 않았다.
- ①의 굵기 측정은 현재와 거의 같은 시간이다(+4%).
