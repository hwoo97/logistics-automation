### F04 · 유턴 맞추기 세기(0.3~0.45)가 시동 문턱 이하임 — 실차 확인 필요

- 고칠 방향: 트랙 바닥에서 배터리 만충 · 7.0V 두 조건으로 제자리 회전이 시작되는 최소 세기를 측정한다. `align_min`을 그 값보다 높게 두거나, 접근 동작처럼 짧은 시동 세기를 준다. 시험 기록에 배터리 전압을 함께 적는다.

### 4.3 영상 판정 (4건)

- **E102** · `/line/tune` 값이 inf이면 `line_node`가 종료됨 — 코드 확인
  - `/line/tune`에 inf · -inf · 1e400 같은 값을 직접 발행하면 `int(float(value))`가 OverflowError를 낸다. `except ValueError`에 해당하지 않아 `line_node`가 종료되고, respawn이 없어 다시 실행되지 않는다.
  - 앱 경로는 `parse_command`가 범위를 검사하므로 해당하지 않고, `ros2 topic pub` 같은 직접 발행에서만 발생한다. 0과 음수도 검사하지 않는다(CONFIRM 0 = 첫 프레임 확정 · LINE_END 0 = 한 장만 놓쳐도 확정).
  - 근거: `agv_vision/line_node.py:108 · 111 · 142 · 143` · `agv_protocol/messages.py:55 · 83 · 129`
  - 고칠 방향: `except (ValueError, OverflowError)`로 넓히고, `line_node`에서도 `TUNE_RANGES`와 같은 범위를 검사한다.
- **I02** · 마커의 검정 기준이 라인 판정과 다름 — 실차 확인 필요

  - 그늘 때문에 갈래 스티커 아래 창의 바닥이 화면의 밝은 영역보다 약 28% 넘게 어두우면 center로 판정된다. 그러면 첫 프레임에서 직진을 확정해(J01) 회전할 분기점을 지나친다.
  - 반사로 center 스티커가 좌우로 판정되는 경우에는 멈춘 뒤 5프레임 중 3프레임 이상 같은 방향이어야 회전하므로, 정지 위치에서도 반사가 이어지고 그 방향에 갈래가 있을 때만 잘못 회전한다.
  - 근거: `agv_vision/marker.py:42 · 86` · `agv_vision/line_detect.py:104 · 105 · 109` · `agv_vision/marker_node.py:21` · `agv_control/drive.py:490 · 531`
  - 고칠 방향: `marker._black`을 `line_detect.black_mask`로 바꾸고, 검정 파라미터를 `line_node`와 같은 값으로 공유한다.
- **I03** · center 창이 스티커 바로 아래에 고정되어 일부 배치에서 center를 놓침 — 실차 확인 필요
  - center 창은 스티커 x 바로 아래(지름 0.8~1.8 · 좌우 ±0.3)에 고정되고, `angle`은 `line_x` 계산에만 사용한다.

### 4.4 하드웨어 · 설정 (10건)

- **B02** · 영상 설정(5fps · 320×240 · 품질 50)이 측정된 블루투스 처리량을 넘을 수 있음 — 실차 확인 필요
  - 처리량 기록은 10-26 1회(데스크톱과 USB 동글 · 거리 미기록)뿐이며, 286 kbps는 팀이 추정한 필요량 약 600 kbps보다 낮다.
  - 600 kbps는 프레임 15 KB를 가정한 추정이고 실제 프레임 크기 · FPS · 지연 측정이 없다. 시연 노트북으로 측정한 처리량과 두 채널 동시 시험(블루투스 점검 항목 3 · 4 · 5)이 없다.
  - 근거: `agv_bringup/config/params.yaml:204 · 205 · 206` · `03_setup/bluetooth/README.md:80 · 97 · 99 · 102 · 103` · `02_design/development_plan.md:73`
  - 고칠 방향: 3m 처리량과 두 채널 동시 시험을 기록한다. 결과에 맞추어 `video_fps` · `jpeg_quality` · `video_size`를 낮추고, 영상 켬 · 끔에서 STATUS · ACK 지연을 비교한다.
- **E302** · PCA9685 I2C 오류 · 재전원을 처리하지 않음 — 실차 확인 필요
  - 드라이버와 `pantilt_node`에 I2C 오류 처리 · 재초기화가 없다. 콜백 안의 I2C 쓰기에서 OSError가 발생하면 노드가 종료된다(respawn 없음). 이후 mission은 SIGN 자세 대기에서 10초 뒤 E_APPROACH가 되고, CHECK_SIGN에서는 제한 시간이 없어 멈춘다.
  - 제어보드가 Pi에 전원을 공급하므로 배터리를 끄거나 교체하면 Pi도 다시 시작된다. 남는 경우는 Pi를 별도 전원으로 켠 책상 시험과 주행 중 일시적인 I2C 오류이다.

- **B01** · standalone launch · 가짜 차량에 연결하면 앱에 저장된 트랙 매핑이 빈 값으로 덮어쓰임 — 코드 확인
  - standalone(`s0_hw` · `s1_line`)이나 `main.py --fake`로 연결하면 브리지 · 가짜 차량의 `track_map`이 비어 있어 연결 직후 `MAP WORK=- DROP_A=- DROP_B=- PARK=-`를 전송한다. 앱은 `config.json`의 `track_map`을 `{}`로 저장한다.
  - 앱을 다시 실행하면 매핑 표가 모두 「?」이고 「초기 설정을 먼저 하세요」가 표시된다. START 판정은 차량이 하므로 영향은 앱 표시에 그친다. `agv.launch.py`로 다시 연결하면 복구된다.
  - 근거: `agv_bt/bridge_core.py:27 · 71 · 123` · `laptop_app/ui/main_window.py:60 · 105 · 301` · `laptop_app/ui/user_tab.py:94 · 101` · `laptop_app/fake_vehicle.py:40 · 84`
  - 고칠 방향: standalone 브리지는 연결 때 MAP을 전송하지 않거나, 앱이 「-」만 있는 MAP은 저장하지 않는다.
- **B07** · `agv_vision`의 `package.xml`에 `std_msgs` · `rcl_interfaces` 실행 의존성이 없음 — 코드 확인
  - `line_node`가 직접 사용하는 `std_msgs`와 `rcl_interfaces`의 `exec_depend`가 없다. 다른 패키지의 전이 의존으로 설치되므로 현재 실행에는 문제가 없다. `agv_bt` 의존을 빼면 `std_msgs`가 빠질 수 있다.

  - 고칠 방향: `<exec_depend>std_msgs</exec_depend>`와 `<exec_depend>rcl_interfaces</exec_depend>`를 추가한다.
- **D05** · standalone DEV RESET이 카메라 · 목적지 색 · LED · 7세그먼트를 되돌리지 않음 — 코드 확인

  - 고칠 방향: standalone 분기에서도 pose LINE · target NONE · LED OFF · 7세그먼트 표시를 발행하거나, 규약에 standalone 범위를 따로 적는다.
- **E405** · 가짜 차량이 DEV RESET · 주행 중 거부 · STOP의 U턴 정지를 구현하지 않음 — 코드 확인
  - 가짜 차량 `handle_dev`에 RESET 분기가 없어 DEV RESET에 ACK만 전송하고 상태 · 진행 중인 시험이 그대로 남는다.

  - 근거: `laptop_app/fake_vehicle.py:162 · 186 · 190 · 268` · `agv_bt/bridge_core.py:111` · `laptop_app/README.md:36`
  - 고칠 방향: `handle_dev`에 RESET(주행 예약 삭제 · 상태 머신 RESET 반영 · EVENT RESET)을 추가한다. STOP에서 U턴 타이머도 지우고 DEV DRIVE DONE E_ESTOP을 전송한다. 가짜 주행 중에는 MANUAL ON · DEV WHEEL · DEV DRIVE(STOP 제외)를 NAK로 처리한다.
