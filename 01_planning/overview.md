# 개요서 — ROS 2와 Teachable Machine을 활용한 비전 인식 물류 AGV

> 프로젝트명: **ROS 2와 Teachable Machine을 활용한 비전 인식 물류 AGV**
> 최종 갱신: 2026-10-23

## 1. 프로젝트 목적
작업장에서 카메라와 AI로 화물 종류(원/사각형 이미지)를 인식하고, 종류별로 정해진 하차 지점까지 라인트레이싱으로 자동 운반·분류하는 소형 물류 자동화 차량(AGV)을 Raspberry Pi 5 + Ubuntu + ROS 2로 구현한다.

## 2. 시스템 구성

### 하드웨어
기본 하드웨어는 **JKEMC PiCar-R5 키트**(교재: 광문각 『라즈베리파이5로 구현하는 사물인터넷(IoT)과 인공지능(AI) 자율주행 자동차』)를 사용한다.

| 구분 | 구성 |
|------|------|
| 메인 보드 | Raspberry Pi 5 (별도 구매, 4GB 이상) |
| 제어보드 | 키트 자동차 제어보드 — DRV8835 × 2(모터 4개 개별 구동), PCA9685(서보, I2C), Pi 5V 5A 공급 |
| 브레드보드 | 초음파 센서와 LED 연결용 |
| 카메라 | 키트 카메라 모듈(CSI) 1대 — 판매 페이지 표기는 OV5640, 사진 실크는 "Camera V2.1"(IMX219 계열)이라 **센서 종류 확인 필요** + SG90 팬틸트(서보 2개) — 주행 중 아래(라인), 정지 지점에서 위(도형·표지판) |
| 구동 | 노란색 DC 기어드(TT) 모터 4개 + 바퀴 4개, 스키드 스티어 |
| 거리 센서 | 초음파 센서 1개 (적재 거리 + 장애물 감지 겸용) — **키트에 없음, 별도 구매** |
| 표시 | 빨강·초록 LED 2개 — **키트에 없음, 별도 구매**, (옵션) LCD |
| 통신 | Pi 5 내장 블루투스 (영상 + 제어) |
| 전원 | 키트 7.4V 5200mAh 배터리 → 제어보드, 전압계 |

### 소프트웨어
| 구분 | 구성 |
|------|------|
| 차량 | Ubuntu 24.04 LTS + ROS 2 Jazzy, Python(rclpy) |
| AI | Teachable Machine 이미지 모델 → TFLite로 변환해 Pi에서 추론 |
| 노트북 | Python 앱 — 블루투스로 작업 입력·비상 정지·수동 제어, 영상 확인 |

## 3. 화물과 지점
| 화물(이미지) | LED | 라인 색 | 하차 지점 |
|------|------|------|------|
| 원 | 빨강 | 색 A | 하차 지점 A (표지판 A) |
| 사각형 | 초록 | 색 B | 하차 지점 B (표지판 B) |

- 실제 화물은 없다. 작업장 라인 끝에 고정한 **이미지판**을 화물로 본다.
- 이미지판은 차량이 하차하러 간 사이 **사람이 매회 교체**한다.
- 작업장·하차 지점·대기장소에는 각각 **표지판**을 붙여 카메라로 도착을 판단한다.
- 라인 색, 트랙 배치, 유턴·복귀·주차 경로는 트랙 설계에서 확정한다.

## 4. 단위 기능
| # | 기능 | 구현 방식 |
|---|------|-----------|
| 1 | 모터 제어 | 제어보드 DRV8835 × 2로 TT 모터 4개 개별 제어 (핀맵: [pinmap.md](../02_design/hardware/pinmap.md)) |
| 2 | 라인 트레이싱 | 카메라 영상(하단 영역)으로 라인 위치 추종 |
| 3 | 라인 색 판별 | 카메라 영상으로 분기점에서 라인 색 판별 |
| 4 | 화물·표지판 인식 | Teachable Machine 모델 (원, 사각형, 표지판들, 배경) |
| 5 | 초음파 거리 측정 | 상태에 따라 적재 거리 / 장애물로 해석 |
| 6 | LED 표시 | 빨강 = 원, 초록 = 사각형, 모두 꺼짐 = 빈 차 |
| 7 | 블루투스 제어 | 작업 횟수 입력, 비상 정지, 수동 제어 |
| 8 | 블루투스 영상 전송 | 저해상도(약 320×240) JPEG, 초당 5프레임 안팎 |
| 9 | 물류 처리 알고리즘 | 상태 머신 — 화물 종류 → 하차 지점·경로 결정, 작업 횟수 관리 |
| 10 | 카메라 팬틸트 | PCA9685로 SG90 2개 제어 — 주행용(아래)·인식용(위) 각도 전환 |
| 11 | (옵션) LCD | 완료/남은 작업 횟수 표시 |

## 5. 동작 시나리오
1. 노트북 앱에서 블루투스로 **작업 횟수** 입력
2. 대기장소에서 출발 → 라인을 따라 작업장으로 이동
3. 작업장 라인 끝 이미지판에 접근 → 초음파 **적재 거리 도달 후 3초 유지 = 적재 완료**
   - 그 3초 동안 카메라를 위로 올려 화물(원/사각형) 인식 → 해당 LED on → 카메라를 다시 아래로
4. 화물에 맞는 색 라인을 따라 하차 지점으로 이동
5. 하차 지점 도착 → 정지 → 카메라를 올려 표지판 확인 → 하차 처리(LED off)
   - 주행 중 "정지 지점에 왔다"는 판단 방법은 트랙 설계에서 확정 (정지 마커 / 초음파)
6. 유턴해서 작업장으로 복귀 (그사이 사람이 이미지판 교체)
7. 입력한 횟수만큼 3~6 반복
8. 마지막 작업 후 하차 지점에서 대기장소로 이동 → 대기장소 표지판 인식 → 주차, 작업 종료

## 6. 운영 규칙
- **초음파 해석**
  - 작업장 접근 상태: 적재 거리 도달 후 3초 유지 = 적재
  - 그 외 주행 상태: 가까운 물체 = 장애물 → 정지, 사라지면 재가동
- **블루투스**: 비상 정지 등 제어 명령은 영상보다 우선 처리
- **AI 추론**: 정지 지점(작업장·표지판 앞)에서만 실행해 처리 부담을 줄임

## 9. 주요 리스크
| 리스크 | 대응 |
|--------|------|
| Pi 1대·카메라 1대로 라인 주행 + AI + 영상을 동시에 처리 | 라인은 저해상도 하단 영역, AI는 정지 지점에서만, 영상은 저프레임 |
| 블루투스 하나로 영상 + 제어 | 제어 명령 우선 처리, 4단계에서 속도 측정 후 부족하면 Wi-Fi 검토 |
| 교재·키트는 Raspberry Pi OS + picamera2 기준 | Ubuntu 24.04 + ROS 2 Jazzy 유지 결정 — 교재 코드는 핀맵·로직 참고, 카메라는 libcamera + camera_ros, GPIO는 lgpio |
| Ubuntu에서 키트 카메라 설정 (센서 종류 미확인) | 3단계에서 가장 먼저 센서 확인·검증, 막히면 USB 웹캠으로 대체 |
| Pi 5 GPIO (RPi.GPIO 미지원) | lgpio 사용(모터 소프트웨어 PWM), 서보는 I2C PCA9685 |
| TFLite 런타임 — Ubuntu 24.04 기본 Python 3.12 | 3단계에서 설치 확인 (tflite-runtime 대신 LiteRT `ai-edge-litert` 등 검토) |
| 신호 전압 | 브레드보드에서 초음파 Echo(5V) **분압 필수**, LED 전류 제한 저항 |
| 정지 지점 판단과 AI 추론 시점의 순환 | 트랙 설계에서 정지 트리거(바닥 정지 마커 등) 확정 |
| 4주 기간에 범위가 넓음 (ROS 2 + 카메라 주행 + AI + BT 영상) | 일정 미관리 → 최소한 주차별 마일스톤 권장 |
| 4WD 제자리 유턴 시 미끄러짐 | 4단계에서 유턴 동작 튜닝 |
