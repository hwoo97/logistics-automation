# 개요서 — ROS 2와 Teachable Machine을 활용한 비전 인식 물류 AGV

> 프로젝트명: **ROS 2와 Teachable Machine을 활용한 비전 인식 물류 AGV**
> 최종 갱신: 2026-11-06 — 시나리오는 교수 전달사항 [00_instructor/2026-11-03.md](../00_instructor/2026-11-03.md) 기준 (물품별 두 자리 수량·9개씩 왕복·무작위 순서·18cm 정지·장애물 없음)

## 1. 프로젝트 목적
처음 놓인 트랙을 스스로 돌며 지점 표지판(AI)과 갈래 색 마커의 대응을 익히고(초기 설정), 사용자가 입력한 모양별 화물 개수만큼 상차 지점에서 싣고 모양별 하차 지점까지 라인트레이싱으로 운반하는 소형 물류 자동화 차량(AGV)을 Raspberry Pi 5 + Ubuntu + ROS 2로 구현한다.

## 2. 시스템 구성

### 하드웨어
기본 하드웨어는 **JKEMC PiCar-R5 키트**(교재: 광문각 『라즈베리파이5로 구현하는 사물인터넷(IoT)과 인공지능(AI) 자율주행 자동차』)를 사용한다.

| 구분 | 구성 |
|------|------|
| 메인 보드 | Raspberry Pi 5 (별도 구매, 4GB 이상) |
| 제어보드 | 키트 자동차 제어보드 — DRV8835 × 2(모터 4개 개별 구동), PCA9685(서보, I2C), Pi 5V 5A 공급 |
| 브레드보드 | 초음파 센서와 LED 연결용 |
| 카메라 | **Raspberry Pi Camera Module 3 Wide** (IMX708, 광각, 자동 초점, CSI) 1대 + SG90 팬틸트(서보 2개) — 주행 중 아래(라인·색 마커), 지점에서 위(표지판) |
| 구동 | 노란색 DC 기어드(TT) 모터 4개 + 바퀴 4개, 스키드 스티어 |
| 거리 센서 | 초음파 센서 1개 (표지판 앞 약 18cm 정지) — **키트에 없음, 별도 구매** |
| 표시 | 빨강·초록 LED 2개(실은 화물 모양) + **7세그먼트 1자리**(실은 화물 개수, GPIO 직접 연결) — **키트에 없음, 별도 구매** |
| 통신 | Pi 5 내장 블루투스 (영상 + 제어) |
| 전원 | 키트 7.4V 5200mAh 배터리 → 제어보드, 전압계 |

## 3. 화물과 지점
| 지점 | 표지판 | 하는 일 |
|------|------|------|
| 대기장소 | P | 출발·복귀 지점. 표지판을 바라보고 서 있다가 출발할 때 유턴 |
| 상차 지점(작업장) | W | 화물 상차 — 한 번에 한 모양만 |
| 하차 지점 A | A | 원 화물 하차 |
| 하차 지점 B | B | 사각형 화물 하차 |

| 화물 | LED | 하차 지점 |
|------|------|------|
| 원 | 빨강 | A |
| 사각형 | 초록 | B |

- **실제 화물은 없다.** 앱에서 물품(적·녹)별 수량(각 0~99개)을 입력하고, 상차·하차는 **1초에 1개씩** 세는 것으로 표현한다. 1회 적재는 최대 9개라 넘으면 여러 번 왕복한다. 실은 개수는 차량의 **7세그먼트**(빈 차량 0)에, 실은 물품은 **LED**로 보여 준다.
- **모든 라인은 검정**이고, 분기점에 들어오는 라인 옆에 **목적지 색 마커**(지름 약 2cm 스티커)를 붙인다. 목적지 색이 왼쪽만 = 좌회전, 오른쪽만 = 우회전, 양쪽 = 직진.
- **색과 지점의 대응은 차량이 미리 알지 않는다.** 트랙을 만들 때 지점마다 색을 하나씩 정해 붙이고, 차량은 **초기 설정**에서 색마다 따라가 표지판을 읽어 대응(트랙 매핑)을 저장한다. 결과는 앱에 표시하고 Pi에 저장한다.
- 지점마다 정지선이 하나 있고, 표지판은 정지선 너머 라인 끝에 세운다. 실제 트랙 배치·마커 위치는 [단계별 테스트 트랙](../02_design/track/test_track.md) 실험 결과로 확정한다.

## 5. 동작 시나리오
차량은 대기장소에서 **표지판을 바라보고** 서 있는 상태로 시작하고 끝난다.

**지점 도착 절차 (공통)**: 정지선에서 정지 → 라인을 따라 표지판 앞까지 서행(초음파로 정지) → 카메라를 올려 표지판 확인 → 지점 역할 → 카메라를 내리고 유턴(대기장소에서는 유턴 없이 종료) → 유턴 뒤 처음 만나는 정지선(방금 지점의 정지선)은 멈추지 않고 통과

### 5-1. 초기 설정 (트랙 매핑)
1. 앱 사용자 탭에서 **초기 설정** 버튼
2. 유턴해 출발 → 아직 확인하지 않은 색 하나를 목적지 색으로 정해 따라감
3. 도착한 지점의 표지판을 읽어 "그 색 = 그 지점"으로 저장, 앱에 바로 표시
4. 유턴해 다음 색으로 2~3 반복 (4색 모두)
5. 매핑이 끝나면 대기장소 색으로 돌아와 표지판 앞에 정지 → 완료 (Pi에 저장해 다음 실행에도 사용, 트랙을 바꾸면 다시 실행)

### 5-2. 작업
1. 앱 사용자 탭에서 적·녹 수량(각 0~99개, 한 가지만도 가능)을 입력하고 **작업 시작** (초기 설정이 끝나 있어야 함)
2. 상차 지점으로 이동 → 표지판 확인 → **한 모양만** 1초에 1개씩 상차 (7세그먼트 0 → n, 해당 LED 켬)
3. 유턴 → 그 모양의 하차 지점으로 이동 → 표지판 확인 → 1초에 1개씩 하차 (7세그먼트 n → 0, LED 끔)
4. 남은 수량이 있으면 상차 지점으로 돌아가 2~3 반복 — 먼저 운반할 물품은 **무작위**, 한 물품을 다 옮긴 뒤 다음 물품, 1회 최대 9개
5. 모든 작업이 끝나면 대기장소로 돌아와 표지판 앞에 정지 → 작업 종료

## 6. 운영 규칙
- **정지 지점 판단**: 라인 위 **검은 가로 정지선**을 라인 카메라(OpenCV)로 검출해 정지 → 표지판 앞까지 서행 → 카메라를 올려 표지판(AI)으로 어느 지점인지 확인
- **표지판 배치**: 정지선 너머 라인 끝. 정지선과의 거리는 **장애물 판단 거리 + 10cm 이상**(가까우면 정지선 전에 표지판을 장애물로 보고 멈춤), 그리고 **유턴할 때 정지선이 보이지 않을 만큼**. 표지판 앞에 유턴할 공간을 둔다
- **정지선 통과**: 지점에서 유턴한 뒤 되돌아가며 같은 정지선을 다시 지나므로, **유턴 뒤 첫 정지선 1개는 멈추지 않고 통과** (지점마다 정지선이 하나뿐이라 지점 구분 없이 같은 규칙)
- **초음파 해석**
  - 정지선 → 표지판 접근 중: 표지판 앞 정지 거리 도달 = 정지
  - 그 외 주행 상태: 사용 안 함 (변경 시나리오: 장애물 없음 — 코드에는 끈 상태로 남겨 둠)
- **블루투스**: 비상 정지 등 제어 명령은 영상보다 우선 처리
- **AI 추론**: 표지판 앞에 멈췄을 때만 실행해 처리 부담을 줄임

## 9. 주요 리스크
| 리스크 | 대응 |

| Ubuntu에서 Camera Module 3 설정 | Raspberry Pi 공식 카메라라 libcamera 지원 대상 — 3단계에서 가장 먼저 Ubuntu + camera_ros 동작 검증, 막히면 USB 웹캠으로 대체 |
| 광각 렌즈 왜곡, 자동 초점 흔들림 | 라인·마커는 관심 영역만 사용(필요 시 왜곡 보정), 주행 중에는 초점 고정 |
